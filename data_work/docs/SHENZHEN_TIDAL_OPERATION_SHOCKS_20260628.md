## 已知或待核实的运行 shock

### 文锦北路：2026 年春节后约一个月未实施

用户提供信息：

- 文锦北路在 2026 年春节后约一个月没有实施潮汐车道。
- 原因是地铁施工。

当前日期口径：

- 2026 年春节为 2026-02-17。
- “春节后一个月”暂记为大约 `2026-02-17` 至 `2026-03-17`，精确停运和恢复日期需要用运行日志或官方记录确认。

公开核查到的信息：

- 深圳交警 2026 年自动化潮汐车道通告中，文锦北路工作日 AM 为南行方向，PM 为北行方向；PM 官方口径为 `18:00-20:00`。来源：`https://szjj.sz.gov.cn/ZWGK/TZGG/GGJG/content/post_12770272.html`。
- 深圳公安/交警 2026 年 2 月交通管理月度数据中，`新建深圳至深汕合作区铁路工程` 在 `文锦北路与翠茵路交叉口` 有占道施工记录。来源：`https://ga.sz.gov.cn/ZWGK/TJSJ/TJXX/content/post_12668062.html`。
- 深圳本地媒体关于草埔立交改造的报道显示，施工影响点位与 `文锦北路-龙岗大道/草埔立交` 交通组织有关；报道给出的草埔立交改造施工期为 `2025-03` 至 `2026-06`，旧桥拆除后车辆由原立交组织改为临时平交信号组织，两侧汇入主路车辆和主线车辆均可能受影响。来源：`https://m.dutenews.com/n/article/8844555`。

当前对施工影响的判断：

- 公开材料可以确认施工位置在文锦北路北段附近，核心点位包括 `文锦北路与翠茵路交叉口` 以及草埔立交/龙岗大道衔接区域。
- 公开材料尚不能精确确认占用的是哪一侧车道、哪几个车道、是否每天同一交通组织。
- 从草埔立交改造报道看，这不是一个容易视为“单侧影响”的施工 shock；它更可能通过临时信号、主线汇入、路口排队和上下游瓶颈同时影响双向交通。
- 因此，若用春节后停实施作为 identification，必须把 `潮汐车道未实施` 和 `施工交通组织改变` 分开记录；仅靠速度数据很难自动区分二者。

识别价值：

- 这是一个 on/off 的运行状态变化，可以在同一路段内比较“正常实施日”和“停实施日”。
- 文锦北路有 AM 和 PM 两个相反的 policy-like 方向。停实施期间，若潮汐车道确实不运行，两个方向的容量重分配应消失。

主要风险：

- 停实施原因是地铁施工，施工本身可能改变路段通行能力、车道占用、瓶颈位置、绕行需求和上下游排队。这个事件不是干净的纯政策停运 shock。
- 需要把“潮汐车道不实施效应”和“地铁施工交通组织效应”拆开，否则估计会混合两类冲击。

### 留仙大道：2026-04-24 晚 45 分钟开通

用户提供信息：

- 留仙大道有一次晚 45 分钟开通。
- 日期为 `2026-04-24`。
- 用户说明晚开通后收到较多投诉，表明该事件可能足够显著。

当前日期口径：

- 留仙大道正常窗口为 `17:30-20:00`。
- “晚 45 分钟”暂记为实际开通约 `18:15`，精确实际开通时刻需要用运行日志确认。

识别价值：

- 这是更接近理想的日内运行时点 shock。正常日 `17:30` 开始，shock 日约 `18:15` 开始。
- 可以比较同一路段同一天 `17:30-18:15` 的速度和正常日同一时段速度，也可以看 `18:15` 附近是否出现方向性断点。
- 如果用户投诉集中在晚开通时段，可能提供辅助证据：用户感知的拥堵增加是否对应速度数据中的方向性变化。

2026-06-29 高德速度初步结论：

- 新补买的 `2026-04-20` 至 `2026-04-26` 一周覆盖了事件日。
- 速度数据不支持“17:30-18:15 完全没有政策方向容量改善”的强版本。政策方向在 `17:00-17:30` 极慢，但在 `17:30` 后立即明显改善。
- 更合理的读法是：数据支持 `17:30` 附近开始布局或部分生效，`18:15` 可能是完成设置、完全开通或投诉记录对应的时间点，而不是第一个可检测到的容量变化时点。

主要风险：

- 需要确认当天是否还有天气、事故、施工、节假日前后出行、学校活动等共同冲击。
- 2026-04-24 是星期五。周五晚高峰可能本身不同于周一至周四，因此最好使用相邻周同星期五和同周其他工作日作为对照。

### 其他潮汐车道：通常不会停运

用户提供信息：

- 其他路段一天也没有停。
- 运营能力不会轻易停运；如果停一天，第二天会上新闻。

识别含义：

- 这说明“停运日”非常少，常规数据中不应假设存在很多未记录的停运 shock。
- 其他道路更适合作为正常运行状态下的日内 event-study 或 cross-road comparison，而不是 on/off variation。
- 若要找更多停运或晚开 shock，需要运营日志、投诉记录、交警新闻和社交媒体记录，而不能仅凭速度曲线反推。

## 若要使用这些 shock，需要购买或整理的数据

### 1. 高德或百度高频路段速度

最小单位：

- 每 5 分钟或每 10 分钟速度。
- 需要保留底层 road segment id、方向、geometry、road name、速度、时间戳。
- 不能只买聚合均值，必须能按方向和路段重建 corridor travel time。

文锦北路建议购买窗口：

- 宽窗口：`2026-01-15` 至 `2026-04-30`。
- 至少覆盖春节前正常运行、春节假期、春节后停实施期、恢复运行后数周。
- 如果预算有限，优先购买 `2026-02-02` 至 `2026-03-31`，但需要额外记录春节假期和工作日调休。

留仙大道建议购买窗口：

- 事件日：`2026-04-24`。
- 同周工作日：`2026-04-20` 至 `2026-04-23`。
- 相邻周同星期：`2026-04-17`、`2026-05-01`，其中 `2026-05-01` 是劳动节假期，需要谨慎使用。
- 更稳妥窗口：`2026-04-13` 至 `2026-04-30`，覆盖两个相邻完整工作周和事件日。

每日时间范围：

- 文锦北路 AM：至少 `05:30-10:30`。
- 文锦北路 PM：至少 `16:00-21:30`。
- 留仙大道 PM：至少 `15:30-21:30`。
- 如果预算允许，买全天数据，方便构造凌晨、午间、下午非运行时段 reference 和 placebo windows。

### 2. 精确运行状态日志

需要字段：

- road name
- date
- planned operation start
- planned operation end
- actual operation start
- actual operation end
- whether operated
- abnormal reason
- source of record
- notes on manual operation, signal timing, police deployment, lane closure, late opening

文锦北路必须确认：

- 停实施开始日期
- 恢复实施日期
- 停实施是否同时影响 AM 和 PM
- 深汕铁路/地铁相关施工是否占用车道或改变道路断面
- 地铁施工的空间范围是否覆盖潮汐车道核心段或上下游
- 施工期是否有临时平交信号、匝道封闭、主路导改、公交站或路口转向限制

留仙大道必须确认：

- 2026-04-24 计划开始时间是否为 `17:30`
- 实际开始时间是否为 `18:15`
- 结束时间是否仍为 `20:00`
- 晚开 45 分钟的原因
- 投诉记录发生时间和方向

### 3. 施工、事故、天气和交通管制数据

文锦北路深汕铁路/地铁施工需要：

- 施工路段边界
- 施工起止日期
- 每日施工时段
- 是否占道
- 车道数变化
- 是否有导改或绕行
- 是否影响公交站、路口转向、信号配时

所有 shock 日都需要：

- 天气，尤其降雨
- 事故和临时管制
- 学校开学、考试、大型活动
- 节假日和调休
- 重要路口信号调整

### 4. 空间范围和 control 数据

每个 treatment 都至少需要三层空间：

- core treatment：真实施行潮汐车道的 overlap 路段
- upstream/downstream：核心段上下游 1 km 和 3 km
- candidate controls：远离直接 spillover 的平行走廊

control 的购买范围不要只买近邻。建议同时买：

- 近邻路段，用作 spillover
- 3 km 以外平行路，用作 clean control
- 同一行政片区但非直接连接的道路，用作区域共同冲击 control

### 5. 投诉和舆情数据

留仙大道 2026-04-24 晚开 45 分钟可利用投诉作为辅助证据。需要：

- 投诉时间戳
- 投诉对象路段
- 投诉方向或地理位置
- 投诉文本或分类
- 是否有对应处理记录
- 是否存在新闻或交警通报

投诉不能替代速度数据，但可用于验证速度断点是否被出行者感知。

## 可执行识别设计

### 文锦北路停实施：on/off DID，但要处理施工混杂

基本设定：

```text
speed_{i d t} = alpha_i + delta_d + lambda_t
              + beta Operated_{d} * PolicyDirection_{i,t}
              + epsilon_{i d t}
```

更推荐的版本：

```text
speed_{i d t} = alpha_i + alpha_{i,week} + tau_{area,d,t}
              + beta Operated_{d} * PolicyDirection_{i,t}
              + gamma ConstructionExposure_i * ConstructionPeriod_d
              + epsilon_{i d t}
```

解释：

- `Operated_d` 是当天是否正常实施潮汐车道。
- `PolicyDirection_{i,t}` 要按 AM/PM 分别定义，因为文锦北路早晚方向相反。
- `ConstructionExposure_i` 应由施工边界决定，不应和潮汐车道 treatment 混为一谈。

文锦北路最关键的不是多加 FE，而是要知道施工是否直接改变道路容量。若施工与停实施完全重合，单靠速度数据很难把二者分开。

### 留仙大道晚开 45 分钟：日内局部 event

基本设定：

```text
speed_{i d h} = alpha_i + alpha_{i,d} + lambda_h
              + beta ShockDay_d * PolicyDirection_i * 1[17:30 <= h < 18:15]
              + epsilon_{i d h}
```

更直观的检验：

- 正常日：17:30 后 policy-like 是否相对 opposite 改善
- 2026-04-24：17:30-18:15 是否不像正常日那样改善
- 2026-04-24：18:15 后是否出现方向性变化

建议窗口：

- `16:30-19:00` 作为主窗口
- `17:00-18:45` 作为小窗口
- `15:30-21:30` 作为完整晚高峰图

### 其他路段：正常运行日的 short-window event

因为用户说明其他路段通常不停止运行，其他路段的识别重点应放在：

- 正常日内实施时点前后
- far controls
- core versus upstream/downstream corridor
- placebo non-active windows

## 购买高德数据的建议优先级

第一优先级：

- 留仙大道 `2026-04-13` 至 `2026-04-30`，全天或 `15:30-21:30`，方向级 road segment 速度。
- 这是最接近日内运行时点 shock 的事件。

第二优先级：

- 文锦北路 `2026-01-15` 至 `2026-04-30`，全天或 AM/PM 覆盖窗口。
- 需要同时购买施工区上下游和远端 controls。

第三优先级：

- 彩田路、红岭路各买至少开通前后多周，或至少买正常运行日多个完整周。
- 这两条路在当前 post-only evidence 中最有希望：彩田路显示 policy-like 被保护、opposite 明显变慢；红岭路显示 policy-like 相对 controls 更快。
