# 彩田路潮汐车道视频数据识别设计

## 理想采集、测量、经验设计与测试阶段证据

更新日期：2026-07-15

## 0. 摘要

本项目拟利用固定机位视频识别潮汐车道重新配置方向性道路容量后，对双向交通流、速度、排队和单位车道运行效率的局部影响。最有识别力的变化发生在两个明确时点：潮汐车道开通时，南向北可用车道由 3 条增加到 4 条，北向南由 4 条减少到 3 条；潮汐车道恢复时，车道配置反向变化。施工期间潮汐车道对两个方向均不可用，应被定义为独立的 transition 状态，而不能与稳定运营状态混合。

理想数据由连续、同步、固定机位的视频构成。每次开通和恢复至少覆盖断点前 60 分钟、完整施工过程和断点后 60 分钟；两个主要机位同时记录同一道路的上游与下游位置，另设一个机位记录车道操作状态更为理想。主样本应包含至少 20 个普通工作日和约 40 次开通或恢复事件。前 5 个采集日用于估计分钟流量方差、缺失率和检测误差，再据此进行正式功效模拟和调整采集规模。

视频被处理为四层数据：原始视频及元数据、车道状态日志、逐车过线事件、固定时间 bin 的相机乘方向面板。核心结果变量包括方向流量、方向流量差、方向平衡、单位车道流量、速度、排队长度、道路占有率和车型构成。两个机位若位于同一路段并可能重复观察同一车辆，不应直接相加。主分析可以把两个机位作为重复测量，采用相机固定效应；展示性汇总可以对同一时间 bin 的同方向流量率取平均，并报告仅保留共同覆盖 bin 的结果。

首选经验设计是多日重复的局部时间断点，并利用两个方向车道数反向变化的结构做方向差分。开通与恢复事件可以按政策含义统一符号后堆叠估计。若能同步采集一条不实施潮汐车道的相近道路，可以进一步构造道路、方向和断点前后的三重差分。这一扩展能更好地吸收晚高峰需求趋势、天气和全市共同冲击。

现有 2026-07-10 测试数据包含 39 个片段和 53,352 条过线事件，其中 51,120 条属于稳定计数样本。出城来源流的描述性比较呈现与车道重新配置一致的方向重分配：南向北流量上升 13.4%，北向南下降 34.6%。进城来源流未完整复现这一模式，单位车道流量也没有稳定上升。两个来源流融合后的简单 level-shift 检验在开通时得到方向平衡增加约 0.22 至 0.28，严格共同覆盖样本得到约 0.33 至 0.34；恢复断点缺少足够的双机位共同 post 样本。局部线性 RDiT 对带宽高度敏感，当前不能构成因果证据。2026-07-09 视频清楚记录了施工过程，可用于验证状态时点和 transition 排除规则，但开通前仅有 2 分 45 秒，不适合作为独立 RDD。

因此，当前阶段可以展示三项内容：视频识别和车道状态标注流程已经可运行；0710 开通时存在与方向性容量调整一致的初步流量重分配；现有覆盖缺口说明下一轮必须采用连续、多日、同步采集。当前不能声称潮汐车道提高了道路容量，也不能把探索性 p 值解释为正式显著性证据。

## 1. 研究问题与目标参数

### 1.1 核心问题

潮汐车道把一条车道从北向南重新配置给南向北。需要回答的不是单一的“车辆数是否增加”，而是以下四个相互关联的问题：

1. 方向性容量变化是否改变两个方向的车辆通过量和流量占比？
2. 新增车道方向的速度是否提高、排队是否缩短？被减少车道的方向是否发生相反变化？
3. 双向总通过量是否变化，还是政策主要重新分配既有道路容量？
4. 单位车道流量、速度和排队的联合变化是否意味着运行效率变化？

### 1.2 目标参数

主目标参数是稳定潮汐运营相对于正常车道配置的局部 reduced-form effect。开通事件和恢复事件分别提供一次方向相反的容量变化。目标结果分为三层：

| 层级 | 结果对象 | 经济含义 |
|---|---|---|
| 第一阶段 | 可用车道数、施工开始、稳定开通、恢复完成 | 证明处理状态确实发生变化 |
| Reduced form | 双向流量、速度、排队、方向差分 | 估计车道重新配置附近的交通响应 |
| 运行效率 | 单位车道流量、速度与排队的联合变化 | 判断通过量变化是否伴随拥堵缓解 |

流量本身不等于容量。若交通需求低于道路容量，新增车道可能不改变流量；若流量不变而速度提高、排队缩短，政策仍可能缓解拥堵。容量或效率结论必须同时使用流量、速度和排队指标。

## 2. 政策状态与事件定义

### 2.1 车道状态

| 状态 | 南向北可用车道 | 北向南可用车道 | 是否进入稳定运营样本 |
|---|---:|---:|---|
| `normal` | 3 | 4 | 是 |
| `deployment_in_progress` | 3 | 3 | 否 |
| `tidal_deployed` | 4 | 3 | 是 |
| `reversal_in_progress` | 3 | 3 | 否 |
| `camera_unstable` | 按实际状态记录 | 按实际状态记录 | 否 |

施工和恢复阶段不是处理后的普通交通状态。该阶段包含施工车辆、警务操作、车辆并线和潮汐车道关闭，其影响与稳定潮汐运营不同。主分析采用 donut 规则排除完整 transition，另把 transition 作为独立结果展示，例如施工持续时间、施工期间损失的可用车道分钟和交通扰动。

### 2.2 两类断点

开通断点定义为潮汐车道已经完成布设并允许第一辆正常社会车辆通行的时点。恢复断点定义为车道调整完成，正常车道配置重新允许稳定通行的时点。至少应记录以下秒级时间：

1. 操作人员或设施进入道路；
2. 潮汐车道开始封闭；
3. 物理车道布设完成；
4. 第一辆车进入重新配置后的车道；
5. 交通流恢复稳定；
6. 恢复操作开始；
7. 正常车道重新开放。

断点时间由操作日志和视频画面共同确定。文件创建时间或网盘下载时间不能作为唯一依据。

## 3. 理想视频采集设计

### 3.1 机位配置

最低配置为两个固定机位，每个机位都能清楚观察两个地理方向：

| 机位 | 位置与功能 | 主要产出 |
|---|---|---|
| Camera A | 路段上游，当前 outbound 来源流附近 | 双向流量、上游排队、进入路段的交通状态 |
| Camera B | 路段下游，当前 inbound 来源流附近 | 双向流量、下游排队、离开路段的交通状态 |
| Camera C（理想扩展） | 能完整看到潮汐车道设施或操作区域 | 秒级车道状态、施工开始和结束、首车通行 |

Camera A 与 Camera B 应保持固定支架、固定焦距、固定分辨率和固定画面方向。机位坐标、镜头朝向、安装高度、道路里程位置和两机位沿道路的距离必须记录。若某个机位无法同时观察两个方向，应增加机位，而不是在不同日期改变同一设备的朝向。

### 3.2 时间覆盖

理想采集窗口为：

- 开通事件：15:30 至 17:30 连续录制；
- 恢复事件：20:30 至 22:30 连续录制；
- 每个事件至少包含断点前 60 分钟、完整 transition 和断点后 60 分钟；
- 录制过程不能在施工时停止，也不能在切换视频文件时留下不可恢复的时间空档。

主样本的操作目标为 20 个普通工作日，每日记录开通和恢复两个事件，共约 40 个事件。前 5 个工作日完成 pilot 后，应依据实际分钟流量方差、相机缺失率和断点效应量进行功效模拟。20 日是数据工程目标，不是未经计算的统计功效保证。

若资源允许，应同步采集一条相近但没有潮汐车道调整的平行道路。控制道路应在道路等级、车道数、晚高峰方向和周边出入口密度上尽量接近彩田路。

### 3.3 时钟同步

两个设备在每日录制前使用同一网络时间校准。建议保留三重时间信息：

1. 设备系统时间；
2. 视频画面中可核验的同步时钟；
3. 人工状态日志中的秒级时间。

录制开始时可让两个机位同时拍摄一次可见的同步动作或播放同一秒级时间界面。每日结束后，用公共交通波动或明确事件复核两路时间偏差。不得使用下载时间替代录制时间。

### 3.4 现场元数据

每日必须记录：

- 日期、星期、是否节假日；
- 天气、降雨、能见度和路面状态；
- 事故、临时施工、警务管制和异常停车；
- 相机 ID、经纬度、安装高度、朝向、焦距、分辨率、帧率；
- 计数线像素坐标和对应道路位置；
- 每个方向的实际可用车道数；
- 潮汐车道操作的全部秒级状态时间；
- 视频缺失、遮挡、抖动、转向和设备更换情况。

### 3.5 文件命名和原始数据保护

建议文件名采用：

```text
YYYYMMDD_cameraID_startHHMMSS_endHHMMSS_original.ext
```

原始视频只读保存。切分视频、压缩版本、标注视频和异常片段存放在派生目录，不覆盖原始文件。每日生成一个 manifest，并为每个原始视频记录文件哈希，以识别误替换或重复下载。

## 4. 采集后的数据结构

### 4.1 原始视频清单 `video_manifest`

| 字段 | 含义 |
|---|---|
| `date` | 录制日期 |
| `camera_id` | 固定机位编号 |
| `source_file` | 原始文件路径 |
| `record_start_local`、`record_end_local` | 经核验的本地录制时间 |
| `fps`、`width`、`height` | 视频技术参数 |
| `camera_lat`、`camera_lon`、`heading`、`height_m` | 机位空间信息 |
| `road_chainage_m` | 沿道路的位置 |
| `clock_offset_s` | 相对于统一时钟的偏差 |
| `coverage_status` | 完整、部分缺失或不可用 |
| `sha256` | 原始文件校验值 |

### 4.2 车道状态日志 `lane_state_log`

| 字段 | 含义 |
|---|---|
| `event_id` | 日期与开通或恢复事件编号 |
| `state_start_local`、`state_end_local` | 状态起止时间 |
| `state` | normal、transition、tidal_deployed 等 |
| `lanes_south_to_north` | 南向北可用车道数 |
| `lanes_north_to_south` | 北向南可用车道数 |
| `first_vehicle_time` | 新状态下第一辆正常车辆通行时间 |
| `source` | 视频确认、人工日志或两者共同确认 |
| `confidence_flag` | 时间是否精确到秒、是否存在不确定区间 |

### 4.3 逐车事件表 `vehicle_events`

每一行表示一条轨迹在一条计数线上的一次过线事件：

| 字段 | 含义 |
|---|---|
| `recorded_at_local` | 过线时间 |
| `camera_id`、`source_video`、`segment_id` | 来源标识 |
| `track_id`、`line_name` | 轨迹和计数线 |
| `geo_direction` | north_to_south 或 south_to_north |
| `vehicle_class` | car、bus、truck、motorcycle 等 |
| `confidence` | 检测置信度 |
| `state`、`counting_status` | 车道状态和样本资格 |
| `line_version`、`model_version` | 计数线与识别模型版本 |

### 4.4 分析面板 `traffic_bin_panel`

主分析单位为 `date × event × camera × geographic direction × 5-minute bin`。面板至少包含：

| 字段 | 含义 |
|---|---|
| `bin_start_local` | bin 起点 |
| `event_time_min` | 相对断点时间 |
| `covered_seconds` | 实际视频覆盖秒数 |
| `vehicle_count`、`flow_per_min` | 过线数和流量率 |
| `lane_count`、`flow_per_lane_min` | 可用车道数和单位车道流量 |
| `mean_speed_kmh`、`median_speed_kmh` | 速度指标 |
| `queue_length_m`、`occupancy_rate` | 排队与占有率 |
| `heavy_vehicle_share` | 大型车辆占比 |
| `state`、`transition_flag` | 运营状态 |
| `quality_flag` | 覆盖、抖动、遮挡和方向混杂质量 |

没有视频覆盖的 bin 保持缺失，不填为 0。部分覆盖的 bin 记录 `covered_seconds`；主结果优先要求完整覆盖，部分覆盖只进入敏感性分析。

## 5. 测量方法

### 5.1 车辆流量

车辆检测和追踪生成轨迹，轨迹跨过预先确认的方向计数线时记录一次事件。对相机 (c)、方向 (d) 和时间 bin (t)，流量率定义为：

```text
q_cdt = crossing_count_cdt / covered_minutes_ct
```

同一 `track_id × line_name` 在同一片段内只允许计数一次。跨片段 track ID 不能直接视为同一车辆。计数线应尽量位于车辆遮挡较少、轨迹已稳定的位置，并在机位不变时保持固定。

### 5.2 地理方向与车道数

`inbound` 和 `outbound` 只表示来源视频流，不等于真实地理方向。地理方向必须由计数线名称和人工核验的道路方向映射。每个 bin 的单位车道流量为：

```text
q_per_lane_cdt = q_cdt / available_lanes_dt
```

施工期间两个方向均按 3 条可用车道记录，但施工样本不进入稳定运营比较。

### 5.3 方向构成

方向差和方向平衡分别定义为：

```text
Delta_q_ct = q_S2N,ct - q_N2S,ct
B_ct = (q_S2N,ct - q_N2S,ct) / (q_S2N,ct + q_N2S,ct)
```

(B=0) 表示两个方向流量相等，(B>0) 表示南向北占比更高。若南向北流量占比为 (s)，则 (B=2s-1)。因此，B 增加 0.20 对应南向北流量占比增加 10 个百分点。B 衡量方向构成，不衡量总流量或道路容量。

### 5.4 速度

首选方法是在同一机位内设置两条沿道路方向分离的虚拟线，并现场测量两线对应的实际道路距离 (D)。同一轨迹跨过两条线的时间分别为 (t_1) 和 (t_2)，速度计算为：

```text
speed_kmh = 3.6 × D_m / (t2_s - t1_s)
```

该方法要求两条线之间的车辆轨迹连续，不能在中间被长时间遮挡。若画面存在明显透视，必须用道路标线、已知距离点或现场测量建立单应性变换，将像素轨迹投影到地面坐标。只有一条计数线且没有空间标定时，不能得到可信的绝对速度。

跨机位速度不应通过简单匹配时间戳计算。若没有可靠的车辆再识别，跨机位数据更适合估计总体流量的时间滞后和路段旅行时间分布，而不是逐车速度。

### 5.5 排队长度与道路占有率

每个方向设置固定道路 ROI。车辆在地面坐标速度低于预设阈值并持续若干秒时被标记为停止车辆。排队长度定义为停止线或计数基准点到最上游连续停止车辆之间的距离。若队尾超出画面，记录为右删失而不是给出虚假长度。

占有率可以定义为 ROI 被车辆检测框覆盖的时间比例，或每个 bin 内平均在场车辆数。速度、排队和占有率共同区分以下情况：

| 流量 | 速度或排队 | 解释 |
|---|---|---|
| 流量上升，速度提高或排队缩短 | 容量利用与运行状态同时改善 |
| 流量不变，速度提高或排队缩短 | 拥堵缓解但需求约束通过量 |
| 流量上升，速度下降或排队增加 | 通过量增加伴随更强拥堵 |
| 流量下降，速度和排队无改善 | 可能是需求变化或测量问题 |

### 5.6 两机位融合

两个机位可能依次观察同一批车辆，因此不得直接把计数相加为道路总流量。推荐两种口径：

1. 回归口径：保留 `camera × direction × bin` 面板，加入相机乘方向固定效应。相机是重复测量来源，不被当作独立需求冲击。
2. 展示口径：在同一 bin 内对两个机位的同方向 `flow_per_min` 取平均，并同时报告严格共同覆盖样本。只有一个机位覆盖的 bin 可以用于辅助图，但必须标记来源数量。

融合前应检查同方向流量的零滞后相关、可能的正向旅行时间滞后、平均比例和结构性偏差。若存在稳定的机位比例差异，可在 normal 稳定共同覆盖时段估计相机校准因子；不得用处理后结果反向校准处理效应。

## 6. 样本构造与质量控制

### 6.1 样本筛选链

```text
原始视频
→ 核验录制时间与相机 ID
→ 按状态和机位变化切分片段
→ 应用版本化计数线
→ 车辆检测与追踪
→ 逐车过线事件
→ 去除同一轨迹同一计数线重复计数
→ 标记方向混杂、抖动、遮挡和缺失
→ 聚合为 1/5/10 分钟面板
→ 构造稳定运营主样本
```

### 6.2 主样本排除规则

以下部分不进入稳定运营主回归：

- `deployment_in_progress`；
- `reversal_in_progress`；
- `camera_unstable`；
- 机位旋转、变焦或画面被长期遮挡的片段；
- 无法确定真实录制时间的片段；
- 完整覆盖不足且无法可靠计算暴露时长的 bin；
- 方向混杂超过预设阈值且轨迹复核不能修正的 segment-line。

短片段可以用于验证状态或计数线，但不能单独作为流量率比较样本。

### 6.3 每日质量报告

每个采集日输出：

- 原始视频覆盖时间线和完全未覆盖区间；
- 计划时长与实际处理帧数比例；
- 每个 segment-line 的事件数、检测置信度和方向混杂率；
- 同一轨迹重复计数率；
- 两机位同方向相关和平均比例；
- 模型版本、计数线版本和异常片段清单；
- 人工抽查的开头、中间、结尾帧及 transition 帧。

## 7. Identification 设计

### 7.1 第一阶段：政策状态是否真实变化

第一阶段不是回归中的工具变量 first stage，而是对处理变量的物理验证。每次事件必须建立一条状态时间线，证明可用车道数从 3/4 变化为 4/3，或从 4/3 恢复为 3/4。施工阶段单独记录为 3/3。状态时点由 Camera C、Camera A/B 画面和人工日志共同确认。

这一层证据回答“何时开始施工”“何时真正开放”“施工持续多久”和“第一辆车何时进入潮汐车道”。若处理时点不清楚，后续时间断点没有明确的 running variable 原点。

### 7.2 单日探索性局部时间断点

对相机 (c)、方向 (d) 和断点附近时间 (t)，最基本的局部线性模型为：

```text
Y_cdt = alpha_cd + tau_d Post_t + beta_minus_d r_t
        + beta_plus_d (Post_t × r_t) + error_cdt
```

其中 (r_t) 是相对于稳定开通或恢复完成时点的分钟数，`Post` 在稳定新状态开始后取 1。施工阶段形成 donut hole 并被排除。单日模型使用 HAC 标准误，但其 p 值只能作为诊断，因为独立事件数仍为 1。

主 bin 为 5 分钟，1 分钟和 10 分钟作为敏感性分析。带宽至少报告 15、30、45 和 60 分钟。若估计随带宽大幅变化，应把结果解释为时间趋势或覆盖结构敏感，而不是稳定的断点效应。

### 7.3 方向差分

车道重新配置对两个方向产生相反的容量变化。对同一相机和时间 bin 构造：

```text
Delta_Y_ct = Y_S2N,ct - Y_N2S,ct
```

开通时预期 `Delta_Y` 上升，恢复时预期下降。方向差分可以吸收同时影响两个方向的部分天气、总需求和检测冲击。它不能消除方向特定的晚高峰趋势、出入口差异或因车道操作产生的绕行。

方向平衡 B 可作为无量纲的辅助结果，方向流量差和两个方向的原始流量仍应同时报告，避免比例指标掩盖总流量下降。

### 7.4 多日重复断点

多日数据允许把每次开通和恢复视为一个事件 (e)。首选面板保留相机、方向、日期和事件标识，并加入相机乘方向固定效应与事件固定效应。开通和恢复可以通过符号标准化后联合估计：

```text
Z_cet = sign_e × (Y_favored,cet - Y_unfavored,cet)
```

开通事件取 `sign=+1`，恢复事件取 `sign=-1`。若政策按预期重新分配方向流量，标准化后的断点系数应为正。每个事件仍应单独作图，防止少数异常日期驱动平均结果。

正式推断应按日期或事件聚类。事件数量有限时，常规聚类标准误可能偏小，应同时报告 wild-cluster bootstrap、随机化或置换型伪断点推断，以及 leave-one-day-out 结果。

### 7.5 有控制道路的差分断点

若同步采集未实施潮汐车道的相近道路，可估计三层对比：

```text
[(favored - unfavored)_treated,post-pre]
- [(favored - unfavored)_control,post-pre]
```

该设计利用方向、道路和断点前后三个维度。关键假设是：没有潮汐车道调整时，处理道路与控制道路的方向差在断点附近具有相近的局部趋势。控制道路不能位于政策引发明显绕行的直接替代路径上，否则会受到 spillover 污染。

### 7.6 事件研究与长期状态比较

事件研究按相对断点时间绘制 5 分钟 bin 系数，重点检查提前变化和恢复路径。全天 normal 与 tidal_deployed 的平均比较只作为状态描述，不作为主因果规格，因为两种状态处于不同时间段并面临不同交通需求。

## 8. 主结果、机制和表格顺序

建议按以下顺序组织经验结果：

1. 第一阶段图：车道状态、施工阶段和视频覆盖时间线；
2. 数据质量表：覆盖率、置信度、方向混杂、双机位相关；
3. 原始事件图：两个方向的流量、速度和排队随相对时间变化；
4. 主 reduced-form：方向流量与方向差分的重复断点估计；
5. 运行效率：单位车道流量、速度、排队和占有率；
6. 双向总量：总流量和总车辆延误；
7. 机制与异质性：车型、拥堵程度、天气、开通与恢复；
8. 稳健性：bin、带宽、donut、共同覆盖、伪断点和日期排除。

## 9. 有效性检验

### 9.1 测量有效性

- 计数线和模型版本在断点处不能同时变化；
- 检测置信度、车型构成和方向混杂率在断点处不应出现机械跳变；
- 相机抖动、遮挡和光照突变必须进入质量标记；
- 两机位融合结果应与各机位单独结果方向一致；
- 对人工抽取的短片进行手工计数，报告 precision、recall 或相对计数误差。

### 9.2 Identification 有效性

- 绘制断点前趋势并检验提前调整；
- 使用多个伪断点，检查模型是否在普通时段频繁产生类似跳变；
- 改变 bin 宽度、带宽和 transition donut；
- 分别估计开通与恢复，检查符号是否反向；
- 保留共同覆盖 bin，避免相机组成在断点处变化；
- 控制天气、事故和临时施工，或删除异常事件日；
- 若使用控制道路，检查处理前局部趋势和潜在绕行 spillover；
- 报告 leave-one-day-out 和相机排除结果。

## 11. 现阶段的初步证据

### 11.1 描述性方向重分配

跨全天稳定片段比较得到：

| 来源流 | 方向 | normal | tidal_deployed | 变化 |
|---|---|---:|---:|---:|
| inbound | 北向南 | 43.80 | 32.98 | -24.7% |
| inbound | 南向北 | 41.51 | 37.66 | -9.3% |
| outbound | 北向南 | 41.10 | 26.89 | -34.6% |
| outbound | 南向北 | 38.69 | 43.87 | +13.4% |

outbound 来源流呈现与车道从 3/4 调整为 4/3 一致的方向变化。inbound 来源流没有完整复现该模式，因此这一结果属于描述性证据，并混有时段需求、机位和覆盖差异。

单位车道流量没有稳定提高。outbound 的北向南和南向北单位车道流量分别下降 12.8% 和 15.0%；inbound 的北向南近似不变，南向北下降 32.0%。双向总流量在两个来源流中也下降。现有结果不支持“容量已经提高”的表述。

### 11.2 两机位一致性

5 分钟 bin 的零滞后相关为：

- 北向南：0.891；
- 南向北：0.682。

只保留每个 segment-line 的主导 raw direction 后，相关提高到 0.938 和 0.734。两个来源流存在共同交通波动，但没有稳定的正向旅行时间 lag 峰。当前证据支持把两个机位视为重复测量，不支持把计数直接相加为道路总流量。

### 11.3 简单融合断点

对同一 5 分钟 bin 内两个来源流的同方向流量率取平均后，方向平衡 B 在开通时增加：

| 窗口半宽 | B 的 level shift |
|---:|---:|
| 30 分钟 | +0.215 |
| 45 分钟 | +0.268 |
| 60 分钟 | +0.282 |

严格要求两个来源流共同覆盖时，45 分钟和 60 分钟窗口的 B 变化分别为 +0.327 和 +0.340。按 (B=2s-1) 换算，这对应南向北流量占比提高约 16 至 17 个百分点。严格样本量仅为 8 和 13 个 bin，不能把模型 p 值作为正式推断。

恢复断点的 all-available B 变化为 -0.040、-0.142 和 -0.166，方向与恢复正常车道配置一致；但严格共同覆盖样本在恢复后只有 1 个 bin，无法估计可靠的双机位结果。

### 11.4 局部线性 RDiT

当前局部线性 RDiT 对带宽高度敏感。opening/inbound 的方向差跳变在 30 分钟带宽为 -13.37 辆/分钟，在 45 分钟带宽变为约 +1.14。recovery/outbound 在 30 分钟和 45 分钟带宽分别约为 +22.94 和 +10.70。断点两侧最近稳定观测之间约有 20 分钟空档，估计依赖趋势外推。

这一结果说明当前数据不支持干净的局部 RDD。它的价值是揭示下一轮必须补齐断点附近连续覆盖。

### 11.5 0709 施工过程证据

0709 核心视频的即时前后比较为：

| 阶段 | 总流量 | 北向南 | 南向北 | B |
|---|---:|---:|---:|---:|
| pre 0:00 至 2:45 | 73.1 | 24.7 | 48.4 | 0.323 |
| post 3:30 至 8:30 | 81.8 | 27.2 | 54.6 | 0.335 |

B 只增加 0.012，不能被解释为强方向重分配。0709 的主要贡献是完整记录施工过程，验证 transition exclusion 和处理时点，而不是提供独立因果估计。

### 第一优先级：补齐断点

## 16. 最终证据链

完整 identification 应形成以下递进关系：

```text
物理状态切换被视频和日志确认
→ 断点附近方向流量、速度和排队发生可重复变化
→ 开通与恢复呈现相反符号
→ 多日结果不由单个日期、相机或带宽驱动
→ 控制道路排除共同晚高峰趋势
→ 单位车道流量、速度和排队共同支持运行效率解释
```

在这条证据链中，现有数据已经覆盖第一步，并为第二步提供了方向一致但不完整的初步证据。下一轮数据采集的任务是补齐断点两侧连续观测，加入速度和排队，并增加独立事件数量。只有完成这些步骤后，才能把“与潮汐车道配置一致的描述性变化”提升为可信的 reduced-form identification。
