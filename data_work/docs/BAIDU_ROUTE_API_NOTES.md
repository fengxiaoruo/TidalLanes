# 百度地图 Web 服务：路径规划 v1 / v2 与批量矩阵（与本项目的关系）

> 说明基于公开文档中的产品定位与参数；**具体计费、配额、高级能力（如未来时刻算路）以 [百度地图开放平台](https://lbsyun.baidu.com/) 当前说明与控制台为准。**

## 1. 产品族：不是「同一接口的两个版本」

在「路径规划」大类下，常见有三类 **不同 URL、不同用途** 的服务（名字里都有 v1/v2，易混）：

| 服务 | 典型 URL | 定位 |
|------|-----------|------|
| 驾车路线规划（**完整 Direction**） | `direction/v2/driving` | 单起点–单终点（含多途经点），返回**可导航级**路线结构（距离、时间、步骤等），能力最全；可配合 `departure_time` 等做**未来/历史**相关能力（文档中部分需**单独申请**）。 |
| 驾车路线规划（**轻量**） | `directionlite/v1/driving` | **轻量**单条算路，途经点数量、能力弱于 v2 完整版；适合对返回结构要求简单、调用量大的场景。 |
| 驾车 **批量算路 / 矩阵** | `routematrix/v2/driving` | 多起点 × 多终点 **ETA/距离矩阵**，**非**完整逐段导航业务；文档说明为满足性能**不做**与完整路径同级的阻断类信息；适合 **OD 批量**估计。 |

本项目 **2500×2 方向** 的规模化需求，优先使用 **矩阵 `routematrix/v2/driving`**，而不是对每条 OD 调 `direction/v2/driving`（否则请求量与解析成本过大）。

## 2. `routematrix/v2/driving` 与「时段 / 畅通」的关系（公开参数）

矩阵接口可设驾车策略 **`tactics`**（文档节选）：

- **11**：常规路线（多数用户常走），耗时与**路况**相关（随**请求时刻**的实时路况变化）。
- **12**：距离较短 + 耗时**考虑路况**。
- **13**：距离较短 + 耗时**不考虑路况**（可理解为更偏「畅通假设」下的时间，与 11/12 的「跟实时堵不堵」含义不同）。

因此：

- **AM / PM（希望体现高峰实时拥堵）**：在公开矩阵能力下，通常用 **11 或 12**，并在**目标时段附近**发起请求，使「实时路况」与早/晚高峰一致；**无法**在普通矩阵上「指定过去某天的 8:00」而不在真实 8:00 附近请求（若需**历史/预测时刻**，需查阅 **Direction v2** 的 `departure_time` / `ext_departure_time` 等是否对您的 AK 开放，且与矩阵不是同一套 URL）。
- **FREE / 畅通基准**：用 **`tactics=13`**，与「高峰+路况」形成对照；**可在任意时间**请求（不依赖当地钟点）。

## 3. 本仓库脚本约定

- `query_baidu_routematrix.py`：对每个 `query_window` 写清 **名义参考时刻**、**tactics**、**说明列**（见 CSV 表头）。
- `run_baidu_travel_panels.sh`：仅需提供 **AK**（参数或环境变量），依次跑 **FREE → AM → PM**（顺序可改），便于复现。

**本地时间校验（默认关闭）**：默认**不因**「不在 8:00/18:00 附近」而拒绝运行，便于 7:00 开跑、长任务跨峰。仅当显式传入 `--strict-clock-window` 时，才用**较宽**的北京时间窗（如 AM 约 05:00–10:30；详见 `query_baidu_routematrix` 与 `NATIONAL_TIDAL_COMMUTING_WORKFLOW.md`）做**可选**检查；可用 `--allow-off-window` 覆盖该检查。

若需 **Direction v2** 的线形 / 未来时刻，应另写小工具单条调用，**不**与当前矩阵批处理混在同一循环里。
