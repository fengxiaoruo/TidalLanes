# 2026-11-03 平台数据、路网与拥堵函数待讨论问题

当前优先核对路段层面的流量与速度匹配，再讨论模型网络和拥堵函数。用户要求 λ 的估计推进到原始有向路段（segment）层面；现有网格边估计保留为诊断。本文记录问题和后续要求，未决定替换网络、函数或参数，也未运行新估计。

## 1. 路网覆盖与速度缺失

上一轮诊断报告：早高峰通勤长度分摊负荷约65%落在模型边上，约23%位于相邻模型节点之间但缺模型边，约12%在模型节点外；全目的负荷落在模型边上的比例为62.5%。这些是特定映射规则下的负荷占比，不直接等于物理道路缺失率。后续应核查映射规则、样本范围和道路等级。

需要比较两条路线：

- 沿用网格，以联通 RN 路网或 OSM 加实际经过记录补充网络。先查 Speed 的06号经过表是否支持可靠的路段旅行时间，包括时间精度、连续经过记录、方向和地图匹配。若缺速度，评估道路等级、限速或邻近同类道路推算，并区分观测值和填补值，报告填补覆盖及敏感性。经过时间差不能未经检查直接当作路段旅行时间。
- 沿用百度路网。明确缺失 link 如何处理，比较保留现网并报告覆盖、补充连接、限制到流量与速度共同覆盖的道路等方案。不能把缺边车流记作零，也不能未经依据重分配到已有边。

网格本身与模型节点、边集合分别评估；本次未决定重建。稳定车流可作为候选连接证据，还需核查真实道路连通、方向和速度可得性。

流量按走廊内各级道路长度分摊，用时主要来自百度覆盖道路，两者可能不匹配。该不匹配可能影响 λ，偏误方向尚未验证，不能直接认定偏低。先做共同覆盖道路样本，并按主路覆盖程度检验结果。

**用户明确要求：λ 应在 segment 层面估计，不继续以 grid-pair 估计作为最终依据。** 下一步核对 RN 与百度原始有向路段的对应关系，统一路段、方向、时段和车道口径；估计后再讨论如何映射到网格模型。需要同时区分样本经过量、车辆流量、交通需求与密度。

## 2. 用图解释 congestion technology，再选择函数

后续图形应同时展示通行时间水平、速度、局部弹性，并解释水平坐标和对数坐标下的凹凸性。比较现有常弹性形式与 BPR 等候选；示意曲线标明假设参数，数据曲线注明估计方法和不确定性。再考虑潮汐车道容量变化较大时的弧弹性及超饱和区间。

常弹性示意为 t = t̄(q/n)^λ，局部弹性恒为 λ。若采用 BPR，写成：

\[
t=t_0[1+a(q/c)^b],\qquad
\frac{d\log t}{d\log q}=\frac{ab(q/c)^b}{1+a(q/c)^b}.
\]

这里 c 是容量，与 q 使用相同时间单位和一致的车辆口径；应说明 c 是路段总容量还是每车道容量。a、b 是拥堵函数参数，避免与空间模型的 α、β 混淆。BPR 在 a>0、b>1 时，时间对 q 的水平曲线递增且凸；常弹性曲线的水平凹凸性取决于 λ。速度曲线不能直接沿用时间曲线的凹凸判断。

**此前分档的分母是该边观测车流的第95百分位 q95，不是已识别的容量 c。** 因此表中的 q/q95 不能直接标成 q/c，大于1也不代表超过容量。q95 还受样本渗透率、时间窗口及拥堵状态影响。

上一轮对话给出的探索性分档为：低于40%约0，40%至60%为0.03，60%至80%为0.09，80%至100%为0.29，高于100%为0.18。来源是前次对话，尚无已核验的正式输出；须保存可复现计算后再使用。最后一档下降不能仅凭此表解释为达到容量。

“畅通约0.02、拥堵约0.19”来自不同状态下的诊断，可能符合同一非线性函数不同位置的局部斜率，也可能受样本构成、内生性和分档规则影响。不能据此确认共同结构函数，或直接把主线 λ 改成0.2至0.3。按用时切样本的选择问题也须明确。

用户希望随后采用更符合数据与交通实际的拥堵函数。候选选择需比较拟合、自由流下限、容量解释、超饱和处理及反事实表现，并参考 Brad 的文章。文章正式题名、版本和具体函数仍待核对，见 [Brad会议记录](meeting_notes_20261007_brad.md)。

## 3. 在统一 R 人群下计算 purpose-level trip 通勤占比

**用户要求：先统一在 R 的口径下，再按 purpose-level trip 计算。** 下一步从平台规范和代码明确 R 的纳入标准，分子、分母使用相同人群、日期、清洗和方式范围。主统计单位为出行次数，不能继续用混合人群的路段经过负荷占比替代。

需要明确：

- 分母为同一 R 人群在指定时窗内的全部目的 trip；分子为其中通勤目的 trip，依据平台 purpose 编码和停留点规则定义。
- 早晚高峰按出发时间还是经过时间筛选。trip占比与道路在途负荷占比分开报告。
- HW/WH 直接出行与带中间停留的通勤链如何区分；purpose-level 标签能否识别后者，需核查，不能自行将接送、办事等全部算入通勤。
- 全方式与 mode1 分开统计；不同SIM人数、trip次数和路段通过次数不混用。
- 统一抑制门槛和聚合方式，报告无法分类目的及缺失，不把未知目的直接解释为非通勤。

此前早高峰28%、晚高峰23%、边中位数约22%的数字保留为旧口径诊断，不称为统一 R 人群下真正的 trip 通勤占比。其余车流的用途尚未分解，不能把接送、公务、出租网约车等可能来源当作已观测构成。
