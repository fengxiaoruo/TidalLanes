# 观测数据与插补数据的使用规则（2026-11-06）

**规则：估计参数、做路段层面分析时，只用有原始观测的数据，不用插补值。插补只用于构造模型需要的完整路网和格对用时；凡是用到插补的结果，同时报告只用观测数据的版本，两者互相验证。**

## 1. 只用观测数据的场合

- 拥堵函数与λ的估计（边层面、路段层面，OLS与IV）。样本限定为有百度速度观测、且有联通车流的路段或路段小时。
- 路段层面的速度–车流关系、形状曲线、尾部检验等描述性分析。
- 任何以"某条路的速度"作为被解释变量或分档依据的回归。

理由：插补速度来自相邻路段或同等级道路，放进回归会把假设的关系当成数据，弹性会被拉向插补规则隐含的值。

## 2. 可以用插补、但必须对照的场合

- 模型输入的格对拥堵与畅通用时：路由需要一张连通的完整路网，未观测路段只能插补。
- 依赖格对用时的下游结果：基本面反演、Stage 2、选边、反事实。

对照方式：

- 主版本与"只用观测"版本并行。路网上的对应关系为：OSM方案1B（只补短缺口，主线L=300 m）为主版本；OSM方案1A（三级及以上全插补）为上限对照；v3（百度自身网络，只用观测速度）为只用观测的对照。
- 每个格对报告用时中来自观测速度的比例；按该比例分组，检查主要结论在高观测比例的格对上是否成立。
- 两个版本结论方向或排序不一致时，以只用观测的版本为准，并说明差异来源。

## 3. 数据标记

- 路段与弧层面保留 `speed_source` 一列，取值区分：观测、上下游借用、等级中位数、短缺口连接。插补值不得覆盖原始观测列。
- 格对层面保留观测用时占比（按用时加权）和插补长度占比两列。
- 输出目录名中标明插补方案（例如 `_osm1b_L300`、`_osm1a`、`_v3obs`），避免不同版本混用。

## 4. 插补方案的选定与稳健性选项

- 方案1B：L取300 m（2026-11-06定）。600 m作稳健性。补充（2026-11-06）：百度只覆盖约25%的高速车流，1B会排除大段高速；在外部基准出来前，方向不对称以1B为准，通勤成本水平以1A为准，主版本待基准后定。
- 方案1A主规则（2026-11-06暂定）：借相对速度，不借绝对速度。未观测弧的畅通速度取同等级、同环线圈层的观测畅通速度中位数；拥堵时段的速度 = 该畅通速度 × 借来的相对速度（拥堵速度/畅通速度）。相对速度沿行驶方向取上下游3跳以内的观测弧，按距离倒数加权，限同一等级族（高速/干线、主次干、三级）；3跳内没有观测的，取同等级族、同圈层、同时段的相对速度中位数。理由：等级之间速度水平差别大，直接借绝对速度会把快速路的速度借给三级路；拥堵的时间形态在空间上相关，借相对速度只传递拥堵程度。
- 1A的稳健性选项（2026-11-06已做，WORK_LOG）：(a) 借绝对速度；(b) 跳数上限1或5；(c) 后备只按等级、不分圈层；(d) 不借上下游，只用等级中位数（即Speed项目route_v3的现行规则）。
- 稳健性结果（2026-11-06）：1A的格对用时对(a)–(d)不敏感，用时与方向比相关都在0.98以上，不分圈层时用时整体高约12%。1B对缺口长度敏感：L取600 m时方向比与L=300 m的相关只有0.74，方向不对称结论在1B下同时报告两个L。
- 方向：观测速度必须按行驶方向分配到OSM有向弧。Speed项目的 `bj_base` 把同一OSM边上的多个百度路段合并，常含上下行，不能直接用。
